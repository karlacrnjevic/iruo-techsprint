# Azure Cost Estimate

## Scope

The cost estimate is based on the TechSprint Azure architecture defined in
`azure/full` and assumes two developers (`dev1` and `dev2`) and one central
management environment.

The Terraform configuration uses the `West Europe` Azure region by default.

## Resources included

For two developers, the environment contains:

| Resource | Quantity |
|---|---:|
| Moodle virtual machines | 4 |
| Jump Host virtual machine | 1 |
| Managed data disks | 4 |
| OS disks | 5 |
| Internal Load Balancers | 2 |
| Developer Storage Accounts | 2 |
| Azure Files shares | 2 |
| Blob containers | 2 |
| Developer VNets | 2 |
| Management VNet | 1 |
| Public IP addresses | 1 |

The Moodle VMs and Jump Host use the `Standard_B2s` VM size.

Each Moodle VM has an additional 10 GB Standard LRS managed data disk.

## Main cost drivers

The largest expected cost component is compute because five virtual machines
are included in the complete environment.

Additional costs can be generated by:

- VM OS disks
- Managed data disks
- Azure Files capacity and transactions
- Blob Storage capacity and transactions
- Azure Load Balancer usage
- Public IP address
- network data transfer

Virtual Networks, Network Security Groups, Application Security Groups,
Managed Identities and RBAC configuration do not represent the main cost
drivers of this architecture.

## Cost optimization

The environment is designed for testing rather than continuous production use.

Costs can be reduced by:

1. Deallocating developer VMs when they are not being used.
2. Using the B-series VM family for the testing workload.
3. Using Standard LRS storage instead of premium storage.
4. Keeping test storage capacity small.
5. Removing temporary environments after testing.
6. Allowing developers to start and deallocate only their own VMs.

The custom `TechSprint VM Power Operator` role supports this model by allowing
developers to start, restart, power off and deallocate their own virtual
machines.

## Pricing methodology

Exact prices are intentionally not hard-coded into the Terraform
configuration because Azure prices depend on region, currency, subscription
offer and the date of calculation.

For the final project cost calculation, the Azure Pricing Calculator should
be configured for the West Europe region using the resource quantities and
SKUs listed above.

The calculated estimate should be exported or captured as evidence and
included with the project documentation.

## Subscription limitation

The available Azure for Students Starter subscription does not permit
deployment of the complete architecture.

Therefore, the cost model describes the full architecture implemented in
`azure/full`, while the subscription limitation is documented separately in
`azure/starter-test/README.md`.
